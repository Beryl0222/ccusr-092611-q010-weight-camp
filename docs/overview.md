# 减重训练风险台说明

减重训练风险台需要在多方参与、事件顺序不稳定和服务重启的情况下保持记录一致。

## 数据与一致性

- 学员记录有所属方、状态和递增版本；全部状态变化与决定（评估签署、排课、红旗冻结、
  解冻、转诊、退款请求与结算、营期取消、通知入队）写入 `events` 事件表。
- 事件表是一条 SHA-256 哈希链：每条事件的哈希覆盖序号、内容、操作人、时间与前一事件哈希。
  服务打开数据库时重放全链，发现内容改动、断链或编号重复即拒绝服务；`GET /verify`
  可随时复核。
- 写操作在 `BEGIN IMMEDIATE` 事务内完成，失败整批回滚。
- `idempotency` 表按请求键回放首次结果：同一请求键重放返回原结果，换新键重复打卡、
  重复退款结算会被业务规则拒绝，因此不会产生重复考勤或重复结算。

## 关键门禁

1. 医学评估与运动风险评估均已签署，状态才从 `draft` 进入 `ready`，方可排课。
2. 评估签署后不可修改或二次签署；补交资料只追加 `supplements` 记录与留痕事件。
3. 红旗症状触发 `frozen`：当前及后续课程置为 `frozen`，打卡、排课、退款外的动作全部拦截，
   并按通知角色矩阵入队（冻结 → 医务/教练/管理员；解冻 → 教练/管理员；
   转诊 → 医务/管理员；退款 → 财务/管理员；营期取消 → 全部运营角色）。
4. 解冻仅允许构造时登记的授权医务人员；转诊未关闭时不能解冻。
5. 退款批准结算后进入终态 `refunded`；营期取消进入终态 `cancelled`；终态拒绝排课与打卡。

## 角色视图

- 医务人员/管理员：病史、禁忌用药、红旗详情、转诊与评估正文。
- 教练：红旗症状与排课、打卡信息，看不到病史与财务。
- 财务：缴费金额与退款决定，看不到病史与红旗详情。
- 学员：仅本人记录。

`GET /trainees/{id}/actions` 输出每个动作的 `allowed` 与禁止原因，供现场逐项核对；
该投影由与写入路径相同的事实计算，二者保持一致。

## 重启语义

数据库使用文件路径时，学员状态、评估哈希、冻结/转诊/退款决定、通知送达状态与事件链
全部持久化；重启后通知可继续送达，未完成的退款可凭原请求键继续幂等结算。
