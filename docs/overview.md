# 减重训练风险台说明

减重训练风险台需要在多方参与、事件顺序不稳定和服务重启的情况下保持记录一致。

## 一致性边界

- 每次写入在单连接 `BEGIN IMMEDIATE` 事务中完成，公开方法由实例级可重入锁串行化；
  事务失败整批回滚。
- 写命令必须携带 `request_key`，幂等表缓存首次响应；打卡台账与退款台账另外有
  确定性分录 ID 和 `UNIQUE(ref_type, ref_id)` 约束，即使绕过幂等键（换键重试、
  并发请求）也不会产生第二笔结算。
- 实体带 `version` 乐观版本号，每次状态变化递增，视图输出当前版本。

## 风险门禁

排课与打卡前统一计算门禁：两类评估均已签署、未红旗冻结、无未闭环转诊、未暂停、
营期有效。任一不满足即拒绝操作并返回具体原因；`enrollee_view` 同时输出
`gates` 与按角色裁剪的 `actions`，现场可直接核对“谁现在能做什么”。

评估按 (学员, 类型) 唯一存储并记录内容哈希，签署后拒绝再次写入；补交资料进入
独立的追加表，评估行永不更新。

## 红旗与通知

红旗事件写入后，学员置冻结位、所有未开始的已排课程转为 frozen，并生成 red_flag
与 freeze 两条审计事件；通知按事件订阅表投递给指定角色（红旗/冻结 → medic、coach；
退款请求 → finance；退款决定 → owner；关营 → coach/medic/finance），通知保存
pending/delivered 状态，仅同角色（或管理员）可签收。冻结只能由 medic 解除。

## 恢复与防篡改

审计表为哈希链：每条记录保存前一条哈希与本条 `sha256(prev | 时间 | 操作者 |
动作 | 规范化明细)`，`verify_chain()` 可在重启后重算；表上建有禁止
UPDATE/DELETE 的触发器。数据库文件重开后，评估锁定、冻结、转诊、退款决定、
通知送达状态、审计链全部保留，营期取消也不清除任何历史。
